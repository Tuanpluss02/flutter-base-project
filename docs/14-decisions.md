# 14 — Decisions (ADRs)

## How to add or change a decision

Copy `docs/templates/ADR.md`, append a new section here (next number, never reuse), status `Proposed → Accepted/Rejected → Superseded by ADR-XXXX`. Required for: new dependency, change to locked stack, `core/` public API change, lowering a quality threshold, new lint ignore, deviation from any MUST in the docs. Agents may **propose** (status `Proposed`) in a PR but only a human sets `Accepted`.

---

## ADR-0001 Feature-first, three layers per feature — *Accepted*
Context: large team + parallel AI agents need small blast radius and enforceable boundaries. Decision: `features/<f>/{data,domain,presentation}`, shared infra in `core/`, rules in doc 01 enforced by `arch_check`. Consequences: some boilerplate per feature (mitigated by generator T-070); cross-feature reuse only via `domain`.

## ADR-0002 Drift (SQLite) as local database — *Accepted*
Context: need reactive queries, relational filters (price/district/rooms), tested migrations. Alternatives: Isar/ObjectBox/Hive (weaker relational queries/migrations, maintenance risk). Decision: Drift. Consequences: SQL schema management, `build_runner` cost, SQLCipher option.

## ADR-0003 Encrypt local DB with SQLCipher — *Proposed (default on)*
Context: PII/inquiry data on device. Decision: SQLCipher with random key in secure storage; backups disabled. Consequences: native dependency + size increase, key-loss = DB reset + resync (outbox loss mitigated by disabling backups, warning before logout). Reviewer must confirm before T-032.

## ADR-0004 Conflict detection for offline writes — *Proposed*
Context: Directus lacks `If-Match`. Options: (A) server Flow/hook compares `base_server_updated_at` → 409; (B) client pre-flight GET compare. Decision: implement **B** now behind `ConflictDetector` interface; request **A** from backend; swap without touching features.

## ADR-0005 All generated files live in centralized `generated/` folders and are not committed — *Accepted*
Context: parallel agents produce constant merge conflicts in `*.g.dart/*.freezed.dart/*.gr.dart/*.config.dart`, and scattering generated files next to source files clutters feature folders. Decision: route all codegen output (`source_gen|combining_builder`, `freezed`, `auto_route_generator`, `injectable_generator`, `slang`, `drift_dev`) into `lib/generated/**` (plus `packages/*/lib/generated/**` and `test/generated/**`) via `build.yaml` `build_extensions` and CLI output paths; git-ignore `**/generated/`; enforce via `arch_check` A13 (no generated file outside `generated/`, none tracked by git). `make bootstrap`/`make gen` and CI generate them. Consequences: clean source tree, single `.gitignore` pattern, clean clone needs a generation step (~1–3 min); `part` directives in source files use relative paths into `lib/generated/...`.

## ADR-0006 Own `Result`/`Failure` instead of fpdart/dartz — *Accepted*
Decision: tiny sealed `Result` in `core/error` (doc 07). Consequences: fewer dependencies, pattern-matching friendly, no functional-programming learning curve for agents/team.

## ADR-0007 Sync scope: mirror ≤ 5k rows, else query-scoped — *Accepted*
Decision per doc 02 §3. Revisit when any mirror collection exceeds 5k rows or 5 MB.

## ADR-0008 auto_route for navigation — *Accepted*
Context: typed routes, guards, nested tabs, large team. Alternative: go_router (+ go_router_builder). Decision: auto_route. Consequences: codegen dependency; routes declared per feature.

## ADR-0009 Certificate pinning for prod — *Proposed (default on)*
Decision: pin SPKI hashes for API and realtime hosts with at least one backup pin; rotation runbook in `docs/` (T-071). Risk: bricked clients on bad rotation → force-update guard + staged rotation required.

## ADR-0010 Resolved dependency set — *Pending (filled by T-001)*
Record: Flutter/Dart version (FVM), resolved versions of every locked-stack package, any forced pin and reason.

## ADR-0011 Use cases are mandatory for every Bloc data operation — *Accepted*
Context: with optional use cases, business rules drift into Blocs and agents must judge "is this worth a use case?". Decision: Blocs/Cubits depend on use cases only; one class per operation; pass-through allowed; business rules live in use cases; enforced by `arch_check` A16/A17 (doc 10) and DoD (doc 12). Consequences: more small files (generated by T-070), a few extra tests (one delegation test per pass-through), consistent structure and a single place to put rules. Supersedes the earlier "use cases only when non-trivial" guidance.


## ADR-0012 Locked stack completion — *Proposed*
**Context:** docs referenced packages missing from doc 01 §2 (interceptly, codegen companions) and a `debounceRestartable()` transformer that `bloc_concurrency` does not provide. Under rule 7 every such gap blocks an agent.
**Decision:** add `interceptly` + `interceptly_dio` (dev/staging only, tree-shaken from prod via const flavor check) and list all codegen companions (`build_runner`, `freezed`, `json_serializable`, `retrofit_generator`, `injectable_generator`, `auto_route_generator`, `drift_dev`, `envied_generator`, `slang_build_runner`) as part of the locked stack. Implement `debounceRestartable()` ourselves in `shared/bloc/` (T-016) instead of adding `stream_transform`/`rxdart`. Explicitly exclude `workmanager`, `stream_transform`, `rxdart`, `mason`, `sqlite3_flutter_libs` from the base.
**Consequences:** T-001 can resolve the full set without stopping; one small helper to maintain; background execution remains out of scope until a dedicated ADR.
**Affected docs/tickets:** 01 §2, 04 §5, 05 §1, 02 §8, 13 (T-016, T-070).

## ADR-0013 Drift migration artifacts: snapshots committed, derived code generated into `generated/` — *Proposed*
**Context:** `drift_dev schema steps` / `schema generate` output is generated code, which ADR-0005 keeps out of git and inside `generated/`, but `make gen` only ran `build_runner`, so a clean clone could not compile migrations or run `SchemaVerifier` tests.
**Decision:** commit `drift_schemas/drift_schema_v<N>.json` (source). Generate `lib/generated/core/database/schema_versions.g.dart` (steps) and `test/generated/migrations/` (verifier helpers) in `make gen` **before** `build_runner`; both live under `generated/`, are git-ignored, and are checked by A13.
**Consequences:** ADR-0005 holds without exceptions; `make gen` gains one step (skipped while no snapshot exists); migration history lives in reviewed JSON snapshots.
**Affected docs/tickets:** 06 §4, §7, 10 §1–3, AGENTS rule 6, 13 (T-001, T-030), skill `db-migration`.

## ADR-0014 Shared Bloc safe-emit extensions and Drift sync table mixins/helpers — *Proposed*
**Context:** features share identical sync/outbox columns across Drift tables, chunked batch upserts (≤ 500 rows), and safe state emission guards when `restartable()` cancels a handler or a Bloc/Cubit closes. A `BaseBloc` class in `core/` would violate A16 and force inheritance; a generic DAO mixin would bloat DAOs.
**Decision:**
1. Place `SafeEmitterX<S>` (`emit.safe(state)` checking `!isDone`) and `SafeCubitX<S>` (`safeEmit(state)` checking `!isClosed`) in `lib/shared/bloc/safe_emit.dart` (owned by T-016); do not introduce a `BaseBloc` inheritance hierarchy.
2. Provide `mixin SyncedTableMixin on Table` and `mixin OutboxTableMixin on Table` (combined via `with SyncedTableMixin, OutboxTableMixin`) plus `SyncRowStatusConverter` (explicit `wireValue`, never `textEnum`), a `SimpleSelectStatement` extension for `is_deleted = false`, and top-level `upsertChunked(db, table, rows, chunkSize: 500)` in `lib/core/database/` (owned by T-030).
**Consequences:** zero boilerplate for mandatory sync columns and chunked upserts while keeping `arch_check` A16 intact and avoiding deep inheritance.
**Affected docs/tickets:** 04 §5, 06 §2–3, 13 (T-016, T-030), skills `add-bloc`, `add-synced-entity`, `add-offline-write`.
